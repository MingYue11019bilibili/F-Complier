## F 语言是什么

F 语言全称 **Forty-five**，取自 `/` 与 `\` 在纸面上约 45° 的书写角度。

它是一门娱乐性质的语言，设计哲学是「梦到什么写什么」。它不追求实用，不追求性能，也不追求被任何人喜欢。它只做一件事：把第一行的 `/` 和 `\` 翻译成 C 或 C++ 源代码，然后交给 gcc/g++ 去编译。

F 语言不是生产工具。但它是一个**完整**的玩具：能编译，能报错，能生成可运行的程序，还有一部《F语言规范条例》。

## 快速开始

### 构建

**环境要求**

| 项目 | 要求 |
|------|------|
| Visual Studio | 2019 或更高版本 |
| 平台 | x64（推荐） |
| C++ 标准 | C++17 或更高 |

也可以直接用命令行构建：

```bash
g++ -std=c++17 -O2 CompilerMan.cpp -o kfc
```

**使用 Visual Studio**

1. 打开 `kfc.slnx`
2. 配置选 **Release**，平台选 **x64**
3. 按 F7 生成解决方案
4. 输出：`x64\Release\kfc.exe`

### 写一个 F 程序

新建 `hello.kskbl`，第一行写：

```
/\///////\
```

执行：

```bash
kfc hello.kskbl -c
```

你会在同目录得到 `hello.exe`，运行后输出：

```
Hello, world!
```

## 语言规则

### 第一行是唯一的现实

F 语言只认第一行。其余所有行都被视为注释，编译器不会看第二眼。

第一行只能由 `/` 和 `\` 组成。出现其他字符会被视为非法入境。

### 首字符决定语言

| 首字符 | 目标语言 | 生成文件 | 编译器 |
|--------|---------|---------|--------|
| `/` | C | `.c` | gcc |
| `\` | C++ | `.cpp` | g++ |

### 编码规则

从第一行第二个字符开始，每 **9 个字符**为一组：

- `/` 代表 `0`
- `\` 代表 `1`

按顺序拼成一个 9 位二进制数，转换为一个 **3 位八进制数**，取值范围 `000` ~ `777`。

| 八进制 | 十进制 | 含义 |
|--------|--------|------|
| `000` ~ `377` | 0 ~ 255 | ASCII 字符 |
| `400` ~ `777` | 256 ~ 511 | 内部代码 |

八进制 `400` 及以上是内部代码。命中后**立即停止解析**，用内部代码处理函数的返回值覆盖产物文件，不再进入编译阶段。

### 编码段长度

第一行除去首字符后，长度必须是 **9 的倍数**。

### 注释区静音

第一行之外的所有内容都是注释。注释区**不允许**出现 `/` 或 `\`。

- 出现 `/`：违反《F语言规范条例》第四章 4.1 条
- 出现 `\`：违反《F语言规范条例》第四章 4.2 条

### 编码示例

| 第一行 | 编码段 | 二进制 | 八进制 | 结果 |
|--------|--------|--------|--------|------|
| `////\///\\` | `///\///\\` | `000100011` | `043` | ASCII `#` |
| `//\\\\\\\/` | `/\\\\\\\/` | `011111110` | `376` | ASCII `0xFE` |
| `/\///////\` | `\///////\` | `100000001` | `401` | 内部代码 0401 |
| `\/////////` | `/////////` | `000000000` | `000` | ASCII NUL |

## 命令行用法

```
kfc <input.kskbl> [-i <header>] [-c] [-o <output>]
```

| 参数 | 含义 |
|------|------|
| `<input.kskbl>` | 必填，F 语言源文件 |
| `-i <header>` | 指定头文件（必须 `.zd.zdjd` 或 `.jd.zdjd` 结尾） |
| `-c` / `--compile` | 生成 C/C++ 代码后直接调用 gcc/g++ 编译 |
| `-o <path>` | 指定输出路径 |
| `-h` / `--help` | 显示帮助 |

### 示例

```bash
# 只生成 C/C++ 代码
kfc hello.kskbl

# 生成并编译
kfc hello.kskbl -c

# 指定头文件
kfc hello.kskbl -i hello.zd.zdjd -c

# 指定输出文件
kfc hello.kskbl -c -o hello.exe
```

## 头文件

F 语言的头文件只有两种合法后缀：

| 后缀 | 含义 |
|------|------|
| `.zd.zdjd` | 真的·真的假的 |
| `.jd.zdjd` | 假的·真的假的 |

其余一切后缀（包括 `.h`、`.hpp`、`.zdjd`、`.zd`）一律判定为假，编译器会明确告知：

```
您的头文件是假的！
```

### 自动查找

不指定 `-i` 时，编译器按以下顺序在同目录查找：

1. `<源文件名>.zd.zdjd`
2. `<源文件名>.jd.zdjd`

### 真与假

以 `.zd.zdjd` 结尾的头文件被编译器称为「真的」；以 `.jd.zdjd` 结尾的被称为「假的」。

名字里写「假的」不等于不能用。它只是在使用时会被编译器阴阳一句：

```
—— 真的假的？ 假的！
```

然后照样接纳。

## 内部代码

内部代码的取值范围是八进制 `400` ~ `777`。触发时编译器会：

1. 立即停止解析；
2. 用 `internalCodePayload()` 的返回值**覆盖产物文件**；
3. 不进入编译阶段。

已定义的内部代码：

| 八进制 | 十进制 | 行为 |
|--------|--------|------|
| `0401` | 257 | 生成 C 语言的 Hello World |
| `0402` | 258 | 生成 C++ 语言的 Hello World |

其余内部代码会触发默认分支，写入一段处罚通知。

### 添加新的内部代码

打开 `CompilerMan.cpp`，找到 `internalCodePayload()` 函数，在 `switch` 中添加新的 `case`：

```cpp
case 0403:
    return "// 你的内容\n";
```

返回的字符串就是产物文件的新内容。

## 《F语言规范条例》

《F语言规范条例》是 F 语言的法律文本，规定了源文件、头文件、第一行、编码规则、注释区、编译器、美学与哲学的全部要求。

条例全文附在 `CompilerMan.cpp` 文件末尾，是一份结构完整的规范手册，包含序言、六章正文和附则，当然，我们已经将其单独列成一个[t](FLanguageRules.txt)[xt文件](a/a.txt)（如果你点开了别的什么，那不是 bug，是 feature。可以尝试调整你的鼠标坐标:)。

编译器所有报错都会引用条例的具体条款。
